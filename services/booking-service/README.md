# booking-service

Phase 3 PostgreSQL-backed booking/profile/tier/sales service. See app/routes.py, SQL migrations and root docs/development.md. Configuration/middleware/auth/database handling is shared through wonderland_common but each service remains its own process/image. Public catalog/tier endpoints need no identity; protected mutations/history require signed local developer tokens or configured Cognito access tokens (actual cloud flow unverified). /health and /health/live check the process; /health/ready checks database/schema revision and signing/ownership keys and returns 503 if unavailable. Default authentication fails closed; no AWS/payment credentials are bundled. Actual Docker and cloud execution remain unverified.
