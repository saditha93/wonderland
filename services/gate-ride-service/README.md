# Gate and ride service
Phase 3: protected ticket validation/check-in, ride usage and owned visit history. Uses only visits schema, a public ticket verification key and opaque ownership key; no booking API call or private ticket signing key is required. Ride recording checks the configured attractions API with a bounded timeout/circuit breaker and forwards request IDs. Domain writes and outbox records commit atomically. /health/ready checks SQL revision plus ticket/ownership keys; /health/live checks the process. See docs/development.md and docs/phase-3-outcome.md. No refunds/revocation or queue consumption is implemented.
